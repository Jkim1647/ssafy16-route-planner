# 요구사항 정의서 — 이동 플래너 (Route Planner)

AI 코어 프로젝트 3회차 · Agent 기반 도메인 플래너 서비스 · 광주 3반

## 1. 도메인과 선택 근거

**서비스 한 줄:** "어디서 → 어디로, 언제까지, 얼마 이하로" 가는지 말하면, 외부 API로 **확인한 시간표·소요시간·요금만으로** 도보·지하철·버스·열차·택시를 이어 붙인 문 앞~문 앞 이동 옵션을 계산해 근거와 함께 제안하고, 고른 옵션을 이동 계획으로 저장·관리한다.

길찾기 앱은 "출발 시각을 주면 경로"를 준다. 이 서비스는 **도착 마감·예산·캘린더 일정이라는 제약을 계산해 수단·편·출발 시각을 골라 주고**, 맞는 게 없으면 재계획하며, 좌석·실시간 지연처럼 확인할 수 없는 값은 지어내지 않고 "확인 불가"로 밝힌다.

| 도메인 선택 조건 | 충족 근거 |
|---|---|
| 서로 다른 정보를 주는 외부 API 3종 이상 | 카카오 로컬(장소·좌표), TAGO 열차정보(시간표·운임), ODsay(도보·지하철·버스 구간), 카카오 모빌리티(택시), 기상청 단기예보(강수), ITS 돌발정보(공사·통제) — 6종 실호출 확인 (`docs/기획검증.md`) |
| 판단이 필요한 요청 | 도착 마감 − 도착 구간 − 여유 ≥ 열차 도착, 총요금 ≤ 예산을 계산해야 답할 수 있다. 맞는 열차가 없으면 거점·수단·날짜를 바꾸는 재계획이 실제로 의미 있다. |
| 저장·관리할 결과물 | 이동 계획(날짜, 출발해야 할 시각, 도착 시각, 구간, 총요금). 같은 날 시간이 겹치는 계획은 저장하되 알린다. |
| 위험 도메인 여부 | 해당 없음(건강·금융 아님) → 면책 문구 대신 "좌석·실시간 지연은 확인 불가, 예매처 확인" 고정 안내 |

**대표 요청(제약 포함) 예시**
1. "토요일 오후 2시까지 광주 첨단동에서 서울 강남역, 6만원 이하" — 도착 마감 + 예산
2. "모레 오전 10시 이후 출발해서 부산 벡스코, 제일 빠른 걸로" — 출발 하한 + 우선순위
3. "내일 저녁 6시까지 용산역에서 광주송정역, 환승 적은 걸로" — 도착 마감 + 환승
4. "KTX 출발 30분 전에 취소하면 위약금 얼마야?" — 규정 질문(RAG)
5. "그날 오전 회의 끝나고 출발할게" — 캘린더 일정 반영

## 2. 기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 (이동 플래너) | 우선순위 |
|---|---|---|---|---|
| F3001 | Tool | Tool 명세 정의 및 등록 | Tool의 이름·"언제 쓰는지" 설명·JSON Schema 입력·출력 구조를 정의해 레지스트리에 등록. 외부 API 툴(장소·역·열차·대중교통·택시·날씨·돌발)과 로컬 서버 API 툴(약관 RAG·캘린더)을 구분. 모든 Tool은 `ok/data` 또는 `error(code, message)`로 답하고 예외를 던지지 않는다. | 필수 |
| F3002 | Tool | 후보 조회 Tool | `search_trains`: 출발·도착역 ID와 날짜(기본 오늘)로 열차 편명·출발·도착 시각·운임 후보를 확보. 역 ID는 `find_stations`(카카오 로컬 + TAGO 역 목록)로 연결. 같은 도시 안 이동은 ODsay 경로가 후보. | 필수 |
| F3003 | Tool | 상세정보 조회 Tool | `get_transit_route`(ODsay): 장소↔역 구간을 도보·지하철·버스로 갈 때 소요시간·요금·환승·도보시간. 실패·한도 초과 시 `get_car_route`(택시)로 보충. | 필수 |
| F3004 | Tool | 보조 정보 검색 Tool | `search_places`(장소 이름·주소·링크), `get_weather`(강수확률), `get_road_events`(공사·통제). 결과 없음·예보 범위 밖은 정해진 실패 코드로 반환. | 필수 |
| F3005 | Agent | 사용자 요청 분석 | 기준(출발지·도착지·날짜·도착 마감/출발 하한), 선호(우선순위·허용 수단 — 장거리 본선 기차/고속버스·회피 — 비·택시·버스·지하철·기차), 제약(예산·여유 시간·캘린더)을 추출. 추출 못 한 값은 비워 두고 되묻는다. | 필수 |
| F3006 | Agent | 작업 계획 수립 | 의도별로 필요한 Tool과 순서(장소→역→열차→구간→날씨·돌발)를 작업 목록으로 구성. 인사·사용법은 계획을 건너뛴다. | 필수 |
| F3007 | Agent | Tool 호출 및 결과 통합 | 앞선 Tool 결과(좌표·역 ID)를 다음 Tool 입력으로 전달. 실패는 사유를 기록하고 나머지로 진행. | 필수 |
| F3008 | Agent | 제약 적합성 판단 | 출발해야 할 시각 = 열차 출발 − 승차 여유 10분 − 출발 구간, 도착 = 열차 도착 + 도착 구간. 마감·출발 하한(언제나 현재 시각 이후)·허용/회피 수단·예산·캘린더와 비교. 운임·소요시간을 확인 못 하면 "판단 불가"로 둔다. | 필수 |
| F3009 | Agent | 재계획 | 통과 옵션이 0개일 때만 거점 확장 → 수단 확장 → 전날 출발 순으로 재계획(상한 3회). 이미 받은 Tool 결과는 캐시에서 재사용. 키 오류·한도 초과는 재계획하지 않는다. | 필수 |
| F3010 | Agent | 대화 맥락 유지 | 세션별 조건·직전 제안 카드를 기억하고, 후속 요청은 바뀐 조건만 갱신. Tool 원본 응답은 보관하지 않는다. | 필수 |
| F3011 | Agent | 최종 응답 생성 | 추천 옵션(구간·시각·요금)과 계산 근거·근거 Tool·제외 사유·경고(우천·통제)를 함께 제시. 숫자는 Tool·계산 값만 사용. | 필수 |
| F3012 | 로깅 | 실행 이벤트 발행 | 단계 진입·종료, Tool 요청·응답·소요시간·캐시 여부, LLM 판단(의도와 이유), 재계획을 세션 식별자와 함께 발행. 발행은 구독자를 모른다. | 필수 |
| F3013 | 로깅 | 실행 로그 저장 | 로깅 Agent가 이벤트를 구독해 SQLite에 세션 단위로 발생 순서대로 저장. LLM 미사용. 저장 실패해도 대화는 정상. | 필수 |
| F3014 | 로깅 | 실행 로그 조회 및 삭제 | 세션 목록·상세(순서대로)·삭제 API. 수정 API 없음. | 필수 |
| F3015 | 계획 | 계획 저장 및 조회 | 계획명·날짜·출발/도착 시각·출발지/도착지·구간·총요금·생성 일시 저장, 목록·상세 조회. 같은 날 시간이 겹치면 저장하되 겹치는 계획을 함께 알린다. | 필수 |
| F3016 | 계획 | 계획 수정 및 삭제 | 날짜·시각·장소·이름 수정(겹침 재검사), 삭제, 화면 즉시 반영. | 필수 |
| F3017 | 서버 | 백엔드 API 서버 구현 | FastAPI로 대화·계획·로그·Tool 목록·설정 상태 API를 서로 다른 경로로 제공, Pydantic 요청·응답 모델. | 필수 |
| F3018 | UI | 프론트엔드 화면 구현 | HTML/CSS/JS로 대화·이동 계획·실행 로그 화면, 백엔드 API 연동. | 필수 |
| F3019 | UI | 실행 과정 및 상태 표시 | 실행 단계·Tool 호출 이력을 순서대로, 재계획 지점 구분, 처리 중 표시, Tool 실패·키 누락·호출 한도 안내. | 필수 |
| F3020 | 로깅 | 이상 징후 판단 | 같은 입력 반복 호출, 과도한 재계획, 계획에 없던 Tool 호출을 규칙으로 판정. 근거 없으면 "판정 불가". 이상 실행에만 LLM 원인 진단(판정과 분리 저장). | 심화 |
| F3021 | Agent | Planner·Worker 구조 전환 | 계획(Planner)과 수행(Worker) 분리, 고정 인자 보호, Worker는 고칠 여지가 있는 실패에서만 LLM 판단, 로깅 Agent 검증 → 재구성. 단일 모드와 비교표. | 심화 |
| F3022 | Tool | RAG 검색 Tool | 철도·고속버스 운송약관(환불·위약금·지연 보상)과 기상특보 행동요령을 Chroma에 색인해 검색. 출처 제시, 색인 없으면 `NO_INDEX`. | 심화 |
| F3023 | Tool | 캘린더 연동 Tool | 일정 조회·등록 Tool. 로컬 저장소 먼저, Google Calendar로 교체. 등록은 계획 ID만 입력. 조회한 일정은 이동 시간대 겹침 판단에 반영. | 심화 |

## 3. 비기능적 요구사항

| 번호 | 분류 | 요구사항명 | 상세 |
|---|---|---|---|
| NF3001 | 보안 | API 키 관리 | `.env`로만 관리, `.gitignore` 등록, 코드·응답 샘플에서 키 제거 확인 |
| NF3002 | 보안 | 화면 노출 제한 | 화면·로그에 키·오류 원문(키가 든 URL) 미노출, 설정 상태는 boolean만 |
| NF3003 | 안정성 | Tool 실패 처리 | Tool은 예외 대신 실패 코드 반환, 한 Tool 실패해도 응답 생성 |
| NF3004 | 안정성 | 재계획 상한 | `MAX_REPLAN=3` |
| NF3005 | 성능 | 응답 시간 | 영구 캐시, 요청당 LLM 최대 2회(gpt-5-nano, reasoning_effort=minimal) |
| NF3006 | 구조 | 모듈 분리 | `backend/`(api·agent·tools·events·db)와 `frontend/` 분리, Tool 파일 분리 |
| NF3007 | 법·윤리 | 출처와 이용 조건 | 외부 API 출처·호출 한도·약관 기록, ODsay 하루 30회·ITS 월 100회 쿼터를 코드로 강제 |
