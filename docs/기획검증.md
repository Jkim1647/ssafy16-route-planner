## 2. 전환 게이트 (설계 4장) — **통과**

- (a) TAGO 열차가 미래 날짜(+1/+3/+7일) 시간표와 운임(`adultcharge`)을 준다 → **예**. 따라서 `estimated` 대체 조회는 필요 없음(코드는 남겨 두되 정상 경로는 요청 날짜 그대로).
- (b) 카카오 "광주송정역" → TAGO `nodename` "광주송정" 매칭 → **예** (끝의 "역" 제거로 일치). 서울·용산·부산도 TAGO 목록에 존재.
- 결론: 이동 플래너 도메인 확정. 공연 플래너로 전환하지 않음.

## 6. 설계 변경 (기획 검증 결과 반영)

1. **LLM 비용 절감 (사용자 요청: GMS 한도 축소):** 기본 모델을 `gpt-5-nano` + `reasoning_effort=minimal`로 변경(구조화 출력 1회 1.6초 확인). 요청당 LLM 호출을 **최대 2회(분석 1, 응답 문장 1)**로 제한하고, 계획 수립·재계획은 의도별 규칙 템플릿으로 한다(LLM이 아니어도 F3006 "Tool과 호출 순서 구성" 충족). Worker·로깅 진단 LLM은 설계대로 예외 상황에서만 호출.
2. **역 후보 필터:** 카카오 "기차역" 검색에 신호장·화물역이 섞이므로, TAGO 역 목록에 있는 이름만 후보로 쓴다(설계 6.2 매칭 방식 그대로).
3. **고속버스:** 엔드포인트 미확인 → 확장 2 단계(2일차)에서 활용신청 완료 후 재확인. 안 되면 고속버스는 범위에서 제외.
